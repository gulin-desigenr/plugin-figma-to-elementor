# Plano de Ação: 4.3 Background-Image nativo

## 🎯 Objetivo
Assegurar suporte contínuo para imagens sobrepostas em segundo plano de seções (Containers Elementor). Embora a Fase 3 tenha introduzido a decodificação de imagens para Data-URI, este passo formaliza a inserção correta na aba de estilo para cobrir bugs de formatação JSON no WP.

## 📋 Checkpoints de Desenvolvimento
- [ ] **1. Refatoração de Fallback:** Garantir que se o container tiver cor sólida misturada com um fill de imagem (`IMAGE` node.fills), as propriedades do JSON priorizem a exibição gráfica correta (imagem sobrepondo o fundo sólido colorido).
- [ ] **2. Verificação do Mapping de Imagem:** Validar no `styles/index.js` se a url gerada em Data URI está encapsulada estritamente nas chaves que o Elementor entende (`{ url: "data:image/...", id: "" }`), evitando quebra de parsing no wp-editor.
- [ ] **3. Controle de Tamanho do Fundo:** Inserir parâmetros default para `background_size`, como `"cover"` ou `"contain"`, preenchendo as chaves oficiais para evitar que backgrounds fiquem repetindo (repeat: repeat) feios após colar.
- [ ] **4. Teste de Renderização:** Rodar `npm run build`, exportar um container grande com background complexo do Figma e visualizar num page template do WordPress local ou remoto.

## ✅ Validações
- Teste prático do painel esquerdo do Elementor: A aba Mídia/Estilo deve reconhecer a imagem nativa na propriedade de `background_background` com `classic` ativo.
