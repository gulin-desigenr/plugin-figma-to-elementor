# Plano de Ação: 3.4 Captura e Mapeamento de Font Family para o JSON

## 🎯 Objetivo
Extrair a propriedade `fontName.family` de cada nó de texto no Figma e injetá-la nas chaves corretas do Elementor JSON (`typography_font_family`, `title_typography_font_family`, `description_typography_font_family`), garantindo que ao importar a página no WordPress/Elementor a fonte já venha aplicada automaticamente — sem nenhuma reconfiguração manual. Caso a fonte não exista no ambiente Elementor, o campo é omitido de forma segura e o Elementor aplica sua fonte padrão configurada no Site Settings.

---

## 📋 Checkpoints de Desenvolvimento

### FASE A — Extração (src/styles/index.js)

- [ ] **A1. Leitura de `fontName.family` em `extractTextStyle()`:** Dentro da função `extractTextStyle`, após a extração de `font-size` e `font-weight`, adicionar:
  ```js
  const fontFamily = (node.fontName !== figma.mixed && node.fontName?.family)
    ? node.fontName.family
    : null;
  ```
  - Guard obrigatório para `figma.mixed` (ocorre em nós com múltiplos estilos de fonte misturados).
  - Retornar `fontFamily` como campo do objeto de style: `{ color, size, weight, fontFamily, globalColorId, globalTypoId }`.

- [ ] **A2. Guard de Tipo Seguro:** Garantir que, nos casos em que `node.fontName` seja `figma.mixed` ou `undefined`, o campo `fontFamily` retorne `null` e não cause erro no caller — nunca `throw`, nunca string vazia inesperada.

---

### FASE B — Injeção por Tipo de Widget (src/core/handlers.js)

- [ ] **B1. Widget `heading`:** Após aplicar `typography_font_size` e `typography_font_weight`, adicionar:
  ```js
  if (mainStyle.fontFamily) settings.typography_font_family = mainStyle.fontFamily;
  ```

- [ ] **B2. Widget `text-editor`:** Mesmo padrão do `heading`:
  ```js
  if (mainStyle.fontFamily) settings.typography_font_family = mainStyle.fontFamily;
  ```

- [ ] **B3. Widget `button`:** Adicionar injeção de fonte do texto principal do botão:
  ```js
  if (mainStyle.fontFamily) settings.typography_font_family = mainStyle.fontFamily;
  ```

- [ ] **B4. Widget `image-box` — Título e Descrição:** As variáveis `tStyle` e `dStyle` já são extraídas por `extractTextStyle`. Injetar:
  ```js
  if (tStyle.fontFamily) settings.title_typography_font_family = tStyle.fontFamily;
  if (dStyle.fontFamily) settings.description_typography_font_family = dStyle.fontFamily;
  ```

- [ ] **B5. Widget `icon-box` — Título e Descrição:** Mesmo padrão do `image-box`:
  ```js

  if (dStyle.fontFamily) settings.description_typography_font_family = dStyle.fontFamily;
  ```

- [ ] **B6. Widget `icon-list`:** Injetar na tipografia dos itens da lista:
  ```js

  ```

- [ ] **B7. Função `mapText()` (Texto Avulso):** A função já chama `extractTextStyle`. Adicionar:
  ```js

  ```

### FASE C — Cobertura de Casos Misturados (src/utils/nodes.js)

- [ ] **C1. Helper `getSafeFontFamily(node)`:** Criar função utilitária reutilizável que centraliza a lógica de guard:
  ```js
  export function getSafeFontFamily(node) {
    if (!node || node.fontName === figma.mixed || !node.fontName) return null;
    return node.fontName.family || null;
  }
  ```
  - Pode ser importada em `handlers.js` e `styles/index.js` para evitar duplicação de guard.

- [ ] **C2. Usar `getSafeFontFamily` em `extractTextStyle`:** Substituir a lógica inline pela chamada ao helper, mantendo `extractTextStyle` limpo.

## ✅ Validações

- **Teste 1 — Fonte Única Aplicada:** Criar um texto com fonte `"Roboto"` no Figma, taguear como `heading`, exportar e verificar se o JSON contém `"typography_font_family": "Roboto"` nas settings do widget.

- **Teste 2 — Fonte Diferente em Título vs. Descrição:** Criar um `image-box` onde o título usa `"Montserrat"` e a descrição usa `"Open Sans"`. Verificar se `title_typography_font_family` e `description_typography_font_family` refletem respectivamente as fontes corretas no JSON.

- **Teste 3 — Nó com `figma.mixed` (Fontes Mistas):** Criar um nó de texto com duas fontes diferentes aplicadas em trechos distintos (bold + light de famílias diferentes). Confirmar que o campo `fontFamily` retorna `null` sem quebrar a exportação, e que o campo **não aparece** no JSON final (omissão segura).

- **Teste 4 — Fallback no Elementor:** Importar no WordPress um JSON com `"typography_font_family": "MinhaFonteQueNaoExiste"`. Confirmar que o Elementor não quebra a importação e simplesmente ignora/sobrescreve o valor com a fonte padrão do Site Settings, sem erros no console do WordPress.

- **Teste 5 — Fonte de Sistema (sem Google Fonts):** Usar a fonte `"Arial"` no Figma e exportar. Confirmar que o JSON exportado contém `"typography_font_family": "Arial"` e que o Elementor aplica ou ignora conforme sua configuração interna.

- **Teste 6 — Compatibilidade com Variáveis Globais (3.1):** Garantir que a adição de `fontFamily` não interfere com os campos `__globals__.typography_typography` já existentes — os dois devem coexistir no mesmo objeto `settings`.

- **Teste 7 — Build sem Erros:** Rodar `npm run build` e confirmar que o `dist/code.js` é gerado sem erros ou warnings relacionados à nova lógica.
