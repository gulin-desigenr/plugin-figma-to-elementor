# Plano de Ação: 2.2 Controle de Erros e Validações

## 🎯 Objetivo
Fornecer guias de proteção, feedback não-bloqueante à UI do Figma e interrupções arquiteturais para casos de seleções indevidas por parte do usuário, evitando exportação em White Screen (travamento "mudo" do Elementor) ou payloads JSON corrompidos.

## 📋 Checkpoints de Desenvolvimento
- [ ] **1. Validação de Raiz Múltipla (`export-json`):** Monitorar `figma.currentPage.selection`. Se o usuário tentar exportar múltiplas "roots" desconexas simultaneamente, o script deve interromper a geração e notificar com uma dica de UX orientando o uso do **`[PAGE-WRAPPER]`** com Auto Layout, garantindo a ordem correta.
- [ ] **2. Sanitização Profunda de Null/Empty Nodes:** Apesar do `traverseNode` já pular nós ocultos (`visible: false`), garantir nativamente que widgets mal formados (sem textos vitais) não quebrem o JSON, filtrando vazamentos nas arrays de `elements`.
- [ ] **3. Tratativas de Segurança Localizadas (Try/Catch Isolado):** Como o Try/Catch global já foi adicionado na Fase 2.1, envelopar agora os *handlers específicos* de extração (`mapContainer`, `mapText`, `button`). Se um componente específico falhar (crash), o bloco deve convertê-lo em nulo (sendo ignorado do JSON final) ao invés de abortar o processamento da página inteira, logando um erro silenciado de qual componente falhou.
- [ ] **4. Notícias UX de Sucesso Narrativo:** Exibir notificações de UI assíncronas em tempo real sobre o pipeline (Ex: "Calculando árvore...", "X elementos ignorados por falha", "JSON Copiado com Sucesso").

## ✅ Validações
- [ ] **Trigger Error (Múltipla Raiz):** Selecionar simultaneamente dois containers raiz (soltos na canvas) e apertar "GERAR JSON". O script deve anular o processo com aviso de alerta, preservando o estado de uso.
- [ ] **Trigger Error (Erro Inesperado Exceção):** Testar forçosamente ou simular uma quebra em uma das heurísticas falhando na função nativa do Figma. O `try/catch` deverá engolhar a falha da engine e disparar um log visível.
- [ ] **Sucesso de Exportação Limpa:** Fazer uma exportação válida complexa garantindo que nenhum nó "null" ou vazio tenha sido vazado para a propriedade `elements` do Widget pai.
