# Plano de Ação: 3.1 Resolvabilidade de Variáveis Globais (Cores/Tipografia)

## 🎯 Objetivo
Substituir a exportação engessada de cores e fontes "hard-coded" (hexadecimais estáticos ou CSS solto) pela utilização de Variáveis Globais do Figma traduzidas para o sistema de `Globals` do Elementor. Isso permitirá que os componentes colados herdem instantaneamente o painel de "Site Settings" do WordPress do cliente.

## 📋 Checkpoints de Desenvolvimento
- [ ] **1. Interface de Mapeamento (UI):** Adicionar uma área nas configurações do plugin que permita ao usuário criar um "De-Para" entre o nome do *Color Style* ou *Text Style* no Figma e as chaves de sistema correspondentes no Elementor (Ex: `Primary`, `Secondary`, `Text`, `Accent`).
- [ ] **2. Extração de Identificadores (Figma API):** Durante o traverse do `code.js`, verificar a existência de `node.fillStyleId`, `node.strokeStyleId` ou `node.textStyleId`.
- [ ] **3. Resolução do Estilo:** Se houver um ID, usar `figma.getStyleByIdAsync()` para extrair o nome do estilo do Figma e compará-lo com a tabela de de-para configurada na UI.
- [ ] **4. Construção do Objeto `__globals__`:** Injetar a estrutura do Elementor no JSON, como `__globals__: { text_color: "globals/colors?id=primary" }`, substituindo as chaves rasas em `settings`.
- [ ] **5. Tratamento de Fallbacks:** Se o elemento tiver cor que não está em nenhum estilo (detached) ou se o nome do estilo não foi mapeado, exportar a configuração "hard-coded" (HEX) normalmente.

## ✅ Validações
- **Injeção de Cor:** Colar o JSON gerado importando os estilos e verificar no Elementor se o ícone global (Globo/Bola) da propriedade "Cor" acendeu e carregou a cor referenciada do *Site Settings*.
- **Injeção de Fonte:** Colar o JSON gerado e verificar se a tipografia assumiu a predefinição Global especificada no WordPress em vez de chumbar uma família de fontes pontual.
- **Payload Inspection:** O JSON gerado deve conter chaves `__globals__` claras na raiz do objeto de estilo (`settings`).
