# Plano de Ação: 1.1 Widget `icon-box`

## 🎯 Objetivo
Implementar o processamento back-end do widget `icon-box` no arquivo `code.js`, garantindo que o botão já existente na UI seja funcional e converta componentes visuais do Figma nos atributos nativos do Elementor.

## 📋 Checkpoints de Desenvolvimento
- [ ] **1. Identificar Handler:** Localizar a função `handleManualTag` ou o bloco condicional principal correspondente no `code.js`.
- [ ] **2. Adicionar Lógica Condicional:** Inserir a checagem ou `case` para avaliar se a tag é igual a `"icon-box"`.
- [ ] **3. Extração de Ícone:** Isolar e processar o nó de vetor/ícone da seleção atual no Figma, seja iterando por nomes de layers específicos ou por heurística de estrutura, e extrair os dados gráficos (SVG/Nome).
- [ ] **4. Extração de Textos:** Identificar os diferentes nós de texto e distingui-los estruturalmente ou pelo tamanho da tipografia, separando o `title_text` do `description_text`.
- [ ] **5. Mapeamento de Propriedades Elementor:** Estruturar o payload JSON iterável populando chaves cruciais da anatomia interna desse widget, como: `widgetType: "icon-box"`, propriedades de ícone e cores (`primary_color`).
- [ ] **6. Estrutura de Injeção no JSON:** Revisar o formato JSON derivado, assegurando que o escopo final contém as estruturas hierárquicas necessárias para o copy-paste ou export via API.

## ✅ Validações
- **Teste de UI:** No Figma, selecionar um Componente de "Ícone + Título + Breve Texto" e acionar o processamento de "Icon Box" via interface do plugin.
- **Validação do Payload:** Analisar no log de debugging/output se as chaves da raiz geométrica desse JSON de fato possuem as nomenclaturas descritas.
- **Teste Prático Elementor:** Colar ou importar a estrutura num container do Elementor WordPress garantindo que visualmente o componente seja renderizado com título em sua respectiva tag de cabeçalho, a descrição mapeada via editor de texto embutido e o container do SVG importado perfeitamente.
